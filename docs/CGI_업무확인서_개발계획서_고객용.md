## 1. 이 문서의 목적

CGI가 지금 하시는 판매와 회계 업무를 **한 줄기 흐름**으로 정리하고, 그 흐름이 어디까지 자동으로 이어질 수 있는지 **실제로 1건만 만들어 확인**한 뒤, 다음 단계로 넓혀가기 위한 확인서입니다.

지금 단계에서 **만들어 드리는 것은 "잘 돌아가는 프로그램"이 아닙니다.**
"이 흐름이 실제로 작동하는가"를 숫자와 화면으로 확인해 드리는 **짧은 검증 작업(실증)**입니다.

## 2. 지금은 어떤 상황인가요

### 2.1 지금까지 들려주신 상황 그대로

| | 현재 상황 | 어려움 |
|---|---|---|
| **홈페이지** | 이미 홈페이지가 있고, 개편을 하고 싶어 하십니다 | 개편할 업체가 이미 연결되어 있고, **누가 어디까지 맡는지 아직 정해지지 않았습니다** |
| **스마트스토어** | 네이버 스마트스토어에서 판매하고 싶어 하십니다 | 스마트스토어는 **아직 개설 단계**입니다 |
| **판매할 상품** | CGI가 대리점으로 취급하는 제조사 제품부터 팔고 싶어 하십니다 | 어떤 제품부터 시작할지, 상품 정보는 언제 준비되는지 정해지지 않았습니다 |
| **회계·주문 관리** | 이카운트 ERP를 이미 사용하고 계십니다 | ERP을 쓰고 있어도 **웹에서 들어온 상품 정보와 주문, 회계 전표를 각각 따로 입력**해야 하는 구간이 있습니다 |
| **희망 사항** | 주문·배송과 회계 전표 처리도 자동으로 바뀌면 좋겠다고 하셨습니다 | 어디까지를 지금 할지 정하지 않으면 범위가 무한히 넓어집니다 |

### 2.2 같은 정보를 두 번 넣고 있는 구간

아래는 **구조적으로** 정리한 것입니다. 실제로 몇 건이며 어느 구간이 가장 아픈지는 **이번 실증에서 함께 확인**합니다.

| 구간 | 같은 값을 넣는 곳 | 지금은? |
|---|---|---|
| 상품 정보 | 취급 자료 → 스토어 등록, ERP에 또 등록 | 실제 중복 여부 **확인 예정** |
| 품목·거래처 | 스토어 상품 ↔ ERP 상품/거래처 코드 | 실제 중복 여부 **확인 예정** |
| 주문 | 스토어 주문 → ERP 주문서 | ERP 기본 기능으로 줄일 여지 있음 — **확인 예정** |
| 배송 | 발송·송장·출고 상태 | 실제 중복 여부 **확인 예정** |
| 회계 전표 | 주문 → 매출 전표 | ERP 전표 기능으로 줄일 여지 있음 — **확인 예정** |

  <div class="flow-step flow-step-muted"><span class="flow-num">4</span><b>그 다음 단계</b><span>배송·회계 자동화<br>(실증 후에 결정)</span></div>
</div>

### 3.1 이번 단계의 목표 (이 순서로 봅니다)

1. **한 줄기 흐름이 실제로 이어지는지 확인합니다.** 홈페이지에서 스토어로, 스토어에서 ERP로.
2. **어디에서 같은 정보를 두 번 쓰는지 찾습니다.** 자동화를 할 만한 곳을 숫자로 정합니다.
3. **다음에 뭘 만들지 대표님과 정합니다.** 실증 결과와 우선순위를 함께 보고 결정합니다.

### 3.2 이 카운터에서 지키는 원칙

- **이미 있는 기능을 먼저 씁니다.** 스마트스토어나 이카운트에 이미 있는 연결 기능을 새로 만들지 않고 활용합니다.
- **1건만 확인합니다.** 상품도, 주문도 **한 건**이면 충분합니다.
- **실제로 된 것과 안 된 것을 나눠서 보고합니다.** 안 된 것은 숨기지 않고, 다음에 할 수 있는 일로 바꿔 드립니다.

## 4. 무엇을 먼저 만드나요

가까운 것부터 순서대로 진행합니다. 앞의 단계가 있어야 뒤의 단계가 됩니다.

| 단계 | 하는 일 | 이 단계가 끝나면 | 상태 |
|---|---|---|---|
| **1단계 준비** | 이 문서 확인, 필요한 자료 요청, 계정 상태 점검 | 진행에 필요한 자료와 권한이 준비됨 | <span class="tag tag-check">대기</span> |
| **2단계 상품 정리** | 팔 상품 **1건**의 정보를 정리하고 출처를 표시 | 상품 정보가 어디서 온 것인지 추적 가능 | <span class="tag tag-check">대기</span> |
| **3단계 스토어 개설·등록** | 스마트스토어 개설 지원, 그 스토어에 **상품 1건 등록** | 스토어에서 그 상품이 **실제로 팔 수 있는 상태** | <span class="tag tag-check">대기</span> |
| **4단계 홈페이지 연결** | 홈페이지 상품에 구매 버튼을 달고 연결 | **구매 버튼을 눌러** 스토어 상품 페이지로 이동 확인 | <span class="tag tag-check">대기</span> |
| **5단계 ERP 확인** | 실제 주문 **1건**이 이카운트에 들어오고 전표로 남는지 확인 | ERP 화면에서 주문 1건과 전표를 **직접 확인** | <span class="tag tag-check">대기</span> |
| **그 다음 단계** | 자동화 범위를 정해 실제 시스템으로 구축 | 상용 시스템 | <span class="tag tag-hold">나중에 결정</span> |

> **주의:** 5단계까지가 **짧은 실증(검증 작업)** 입니다. 이 기간은 2일~2주 사이로 예상하고 있고, 정확한 기간과 비용은 **10장**에서 조건과 함께 말씀드립니다. "그 다음 단계"는 상용 시스템 구축으로, 별도의 큰 작업입니다.

## 5. 실제로 확인해 드릴 수 있는 것

아래 6가지를 **모두 확인했을 때** "1차 실증 완료"라고 보고합니다. 하나라도 확인이 안 되면 그 사실도 그대로 보고하고 다음 방법을 정합니다.

| # | 확인 항목 | 어떻게 확인하나요 | 결과 |
|---|---|---|---|
| **1** | 상품 1건의 정보가 정리되고 **근거를 따라갈 수 있음** | 상품 정보표 1건에 출처(어디서 온 자료·사진 경로)와 가격·옵션·ERP 연결 대상이 적혀 있음 | ☐ 완료 ☐ 미완료 |
| **2** | 스마트스토어가 **개설 완료 상태**임을 확인 | 스토어 판매자 화면에서 상품 1건이 실제로 노출되고 구매할 수 있음 | ☐ 완료 ☐ 미완료 |
| **3** | 홈페이지에서 **구매 버튼을 눌러** 스토어까지 이동 | 실제 클릭 1회로 스토어 해당 상품 페이지 도착 (화면 기록) | ☐ 완료 ☐ 미완료 |
| **4** | **실제 주문 1건**이 이카운트에 들어옴 | ERP 주문 수집 화면에서 1건 확인 (수집 시각·주문번호 기록) | ☐ 완료 ☐ 미완료 |
| **5** | 그 주문이 **전표로 정확히** 옮겨짐 | ERP 전표 화면에서 수량·단가·금액·상품을 주문과 대조 (전표번호 기록) | ☐ 완료 ☐ 미완료 |
| **6** | **결과와 남은 문제가 문서로 남음** | 실행 화면·설정값·해결 안 된 항목을 결과물로 제출 | ☐ 완료 ☐ 미완료 |

### 5.1 확인이 안 될 때도 보고드립니다

| 상황 | 보고 방식 |
|---|---|
| 스토어 개설이 아직 안 끝났음 | "개설 진행 중"으로 상태만 적고, 남은 절차를 함께 안내 |
| 실제 주문을 만들 수 없었음 | 어떤 방법까지 시도했는지 적고, 가능한 다른 검증 방법을 제안 |
| 전표 금액이 주문과 달랐음 | 차액이 어디서 생겼는지(할인·부가세 등) 확인해 결과를 그대로 보고 |

**"안 됐다"를 "됐다"고 적지 않습니다.** 대신 **왜 안 됐는지 + 다음에 무엇을 하면 되는지**를 함께 드립니다.

## 6. 실증과 그 다음 단계의 구분

| | 1차 실증 (지금) | 상용 구축 (그 다음) |
|---|---|---|
| **목적** | "되는가?" 확인 | 실제 운영에 쓸 시스템 완성 |
| **대상** | 상품 1건, 주문 1건 | 전체 상품·전체 주문·반복 운영 |
| **기간** | 2일 ~ 2주 (조건에 따라) | 별도 합의 (보수적으로 4주~2개월+) |
| **비용** | 실측 후 견적 | 실증 결과 반영 후 견적 |
| **완료 기준** | 5장의 6개 항목 | 1차 실증 범위 전체가 정상 동작 + 운영 문서·교육 |

> **실증 단계에서는 "전량"을 만들지 않습니다.** 전량을 만들면 검증할 수 없고, 검증 없이 전량을 만들면 위험합니다.

## 8. 필요한 자료와 협조 요청

아래 자료만 준비해 주시면 됩니다. **민감한 정보(비밀번호, 계좌번호 등)는 이 문서가 있는 저장소에 올리지 않습니다.** 필요한 부분만 화면으로 함께 확인하거나, 비식별 처리된 형태로 전달 부탁드립니다.

| # | 필요한 것 | 형식 | 언제까지 | 준비되셨나요? |
|---|---|---|---|---|
| 1 | 스마트스토어 개설·인증 진행 상태 | 스토어 화면 또는 진행 단계 | 스토어 단계 착수 전 | ☐ 준비 ☐ 미정 |

| 3 | 우선 판매할 제조사 제품 목록 (3~5개 정도) | 제품 목록 | 상품 정리 단계 착수 전 | ☐ 준비 ☐ 미정 |
| 4 | 상품 가격·옵션·사진 원본 (1건분) | 파일 | 상품 정리 단계 진행 중 | ☐ 준비 ☐ 미정 |
| 5 | 이카운트 ERP 접속 계정과 사용 중인 메뉴 | 계정 | ERP 확인 단계 착수 전 | ☐ 준비 ☐ 미정 |
| 6 | ERP에 이미 등록된 상품·거래처 정보 | 화면 확인 (민감정보 제외) | 상품 정리 / ERP 확인 | ☐ 준비 ☐ 미정 |
| 7 | 실제 주문 1건을 직접 결제해 볼 수 있는지 | 결제 완료 주문 1건 | ERP 확인 단계 착수 전 | ☐ 가능 ☐ 불가 |
| 8 | 배송·반품·정산을 현재 어떻게 처리하시는지 | 설명 | 상용 구축 설계 전 | ☐ 준비 ☐ 미정 |
| 9 | 자동화가 가장 급한 업무 1순위 | 대표님 결정 | 상용 구축 범위 확정 시 | ☐ |
| 10 | 상용 구축 목표 시점과 예산 규모 | 내부 기준 | 견적 요청 시 | ☐ 준비 ☐ 미정 |
| 11 | 결제 수단·정산 계좌 등 민감정보 취급 범위 | 취급 방침 | 스토어 단계 착수 전 | ☐ 준비 ☐ 미정 |

## 9. 일정과 비용

### 9.1 기간

| | 가장 빠를 때 | 보통 | 여유를 잡을 때 |
|---|---|---|---|
| **1차 실증 기간** | **2 영업일** | **5~7 영업일** | **10~15 영업일 (2~3주)** |
| **무엇을 하는 경우** | 자료·인증·결제가 **즉시** 준비되고 추가 작업이 없을 때 | 자료가 1~2일 늦거나 옵션 연결 등 작업 1개가 추가될 때 | 인증 지연, 자료 재요청, 계정 권한 문제, 홈페이지 업체와 작업이 겹칠 때 |
| **결과물** | 흐름 1회 확인 + 남은 과제 목록 | + 실패 원인 분석 + 상용화 후보 범위 | + 확정된 상용 구축 범위와 견적 근거 |
| **상용 구축 기간** | 4주 내외 | 6~10주 | 12주 이상 |

> **"2 영업일"은 가장 좋은 조건일 때만 가능한 수치입니다.** 보통은 5~7 영업일을 기준으로 보시고, 여유 있는 2~3주 시나리오도 함께 계산에 넣으시면 낙관적인 계획이 되지 않습니다.

### 9.2 비용

**금액은 지금 확정하지 않습니다.** 확정하지 않는 이유는 셋입니다.

1. 실증에서 **실제로 걸린 시간**을 아직 모릅니다.
2. 이카운트와 스마트스토어의 **연결 기능이 어느 수준까지 되는지** 실 계정에서 확인해야 합니다.
3. **가장 급한 업무 1순위**가 정해지지 않아 상용화 범위가 달라집니다.

대신 **구성이 어떻게 되는지** 먼저 말씀드립니다.

| 비용 항목 | 내용 | 실증 단계 | 상용 구축 |
|---|---|---|---|
| **개발·설정 인건** | 실제 걸린 시간 × 표준 일당 | 포함 (2~15 영업일 구간) | 별도 산정 |
| **홈페이지 수정** | 개편 업체가 맡는 부분과 겹칠 수 있어 **PADIEM 비용이 없어질 수 있음** | 구매 버튼 1개 수준 가정 | 미정 |
| **이카운트 추가 옵션** | 이카운트가 이미 제공해 주는 범위에 따라 **추가 비용 발생 여부가 달라짐** | 확인 단계 | 미정 |
| **네이버 스마트스토어 수수료** | **플랫폼 정책에 따라 달라지며 저희가 정할 수 없습니다.** 스토어 규모·매출에 연동 | 해당 없음 | 운영 비용 |
| **결제 대행(PG) 비용** | PG사 계약 기준, 대표님과 PG사 간 과금 | 해당 없음 | 운영 비용 |
| **도메인·호스팅 등** | 기존 홈페이지 환경에 따라 발생 여부 결정 | 여부 확인 | 미정 |

**견적은 1차 실증을 마친 뒤, 실측된 시간을 근거로 2단계와 함께 제출하겠습니다.** 그 전에 금액을 말하면 근거 없는 숫자가 되기 때문입니다.
