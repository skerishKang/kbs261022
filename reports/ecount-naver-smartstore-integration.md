# 네이버 스마트스토어 ↔ 이카운트 ERP 연동 가능성 분석

> 근거: 실계정 화면 실측 (2026-10-22). 계정정보·실데이터 미수록. 본 단계에서 운영 데이터 생성/수정/삭제 없음.
> 근거 데이터: `reports/ecount-mall-support-matrix.csv` (쇼핑몰 34개 × 기능 15개)

---

## 1. 한 줄 판정

> **이카운트 ERP 는 "네이버 스마트스토어 주문·클레임 처리"를 지원한다. 그러나 "ERP → 스마트스토어 상품 마스터 등록"은 지원하지 않는다(상품등록 = X).**
> 따라서 이카운트의 역할은 **주문·재고·회계 백오피스** 로 확정하고, **상품 마스터 배포는 카페24 / 네이버 오픈API 로 분리**하는 것이 현 구조에 맞는 설계다.

## 3. 현시점 상태

| 항목 | 확인 결과 |
|---|---|
| `쇼핑몰등록` 그리드 | **"등록된 데이터가 없습니다."** → 이카운트에 아직 쇼핑몰 채널 미등록 |
| `쇼핑몰품목코드연결` 그리드 | 1행(헤더만), 실제 매핑 없음 |
| `API인증키발급`(E000125) | **"등록된 데이터가 없습니다."** → OAPI 인증키 미발급 |
| 판매자사이트 채널 | Tri-B(삼아스토어)는 **카페24** 운영 → 이카운트 `카페24` 지원 항목으로 주문 수집 가능 |

> **CGI 의 웹 운영 채널은 카페24(삼아스토어) / 삼아사운드(카페24)** 이고, **네이버 스마트스토어는 아직 개설 전**(이슈 #5: "네이버 스마트스토어 신규 개설 전"). 따라서 **스마트스토어 연동은 "개설 후" 작업**이며, 지금 단계는 **연동 준비(채널 등록 · 품목코드 매핑 · 인증키 발급)** 가 맞다.

## 4. 연동 설계

### 4.1 역할 분리 (권장)

```
┌── 소스 ──────────────┐   ┌── 이카운트 ERP ─────────────┐   ┌── 판매채널 ─────────┐
│ Tri-A 삼아사운드(카페24)│   │  품목 마스터(prod_cd)          │   │ 카페24 삼아스토어      │
│ Tri-B 삼아스토어(카페24) │──►│  단가(in_price/out_price)     │──►│ 네이버 스마트스토어    │
│                        │   │  창고·재고                     │   │ (카페24 OR 네이버 API) │
│ [웹자료올리기] 17컬럼   │   │  주문서 → 전표(F7)             │   │                       │
│ + 변경하기(확장필드)    │   │  쇼핑몰품목코드연결              │   │                       │
└────────────────────────┘   │  (prod_cd ↔ 쇼핑몰품목key)      │   └───────────────────────┘
                             │  OAPI 읽기/쓰기                 │
                             └────────────────────────────────┘
```

| 흐름 | 경로 | 비고 |
|---|---|---|
| ① 웹 → ERP 품목 마스터 | **이카운트 `웹자료올리기`** | 신규 개발 불필요. §ecount-item-bulk-registration.md |
| ② ERP → 웹 상품 마스터 | **카페24 API / 네이버 스마트스토어 OpenAPI** | 이카운트 경로 불가(상품등록 X) |
| ③ 웹 주문 → ERP 주문서 | **이카운트 쇼핑몰관리(카페24/스마트스토어2.0)** | 신규주문 O |
| ④ ERP → 웹 재고 | **카페24 API / 각 플랫폼 재고 API** | 이카운트 재고 동기화 기능 없음 |
| ⑤ ERP 재고 → 웹 판매가능 수량 | ④를 통해 간접 | 웹 재고와 ERP 재고 **정합성 관리 필요** |

### 4.2 이카운트가 실제로 담당 가능한 것

1. **주문 수집·처리**: 신규주문 수신, 주문확인(수신/송신), 배송처리, 취소/반품/교환
2. **재고 회계화**: 주문서 → `저장/전표(F7)` 로 매출/재고 전표 자동 생성
3. **회계/세금**: 세금계산서, 전자(세금)계산서, 매출·매입 전표
4. **마스터 관리**: 품목·거래처·창고·사용자·권한
5. **원격 입력**: Customer Portal(거래처가 직접 주문/발주 입력), UserPay

### 4.3 이카운트가 담당하지 못하는 것

1. **ERP → 스마트스토어 상품 마스터 배포** (상품등록 X)
2. **웹 옵션(추가구성품) 수집** (추가구성품 수집여부 X) → Tri-B 의 `추가구성상품` 구조는 이카운트로 이관 불가
3. **재고 웹 반영** (매트릭스에 재고 항목 부재)
4. **공급가 공개** — 공급가(`supply_amt`)는 ERP 전표 입력 시에만 존재. 웹 공개값 대응물 없음

## 5. 네이버 스마트스토어 개설 후 실행 순서 (안)

```
[1] 이카운트  쇼핑몰관리 > 쇼핑몰등록 > 신규(F2)
      쇼핑몰코드 : 스마트스토어2.0 선택
      쇼핑몰명   : (사내 규칙 예: NAVER-SMARTSTORE-01)
      수집처     : 이카운트 수집 / 사용
      진행상태   : 신규
      채널 인증값: 신규 화면에서 스마트스토어2.0 선택 후 노출되는 전용 필드 확인
                   (현재 공통 필드만 실측됨 — §6 미확정)
      → [쇼핑몰추가요청] 로 이카운트 측 채널 개설 요청이 필요할 수 있음

[2] 이카운트  API인증키발급 > 키발급 (OAPI) + IP등록
      → 허용 IP 등록 필수. 인증키 3개월 초과 만료 시 영구 삭제

[3] 이카운트  품목등록 > 웹자료올리기 (17컬럼) → 전량 등록
      → 변경하기 탭으로 브랜드/모델명(cont2/cont3) 2차 반영

[4] 이카운트  쇼핑몰품목코드연결 > 웹자료올리기
      쇼핑몰코드 × 품목코드(prod_cd) × 쇼핑몰품목key(네이버 상품ID)
      → 이 표가 없으면 주문 자동 낙하 불가

[5] ERP→웹   상품 마스터 배포는 별도 파이프라인(카페24 API 또는 네이버 OpenAPI)
      → ERP 품목코드와 웹 상품ID 매핑이 (4)의 키와 동일해야 3중 정합

[6] 검증    신규주문 1건 수신 → 주문서 생성 → 전표 생성 → 재고 차감 → 세금계산서
      → 취소/반품 1건 역방향 검증
```

## 6. 미확정 항목

| 항목 | 이유 | 해소 방법 |
|---|---|---|
| 스마트스토어2.0 의 **전용 인증 필드** (OAuth 클라이언트ID/시크릿/콜백URL 등) | `쇼핑몰등록` 신규 폼은 **공통 필드만** 실측. 채널을 선택해야 노출되는 조건부 필드는 미확인 | 신규(F2) 화면에서 쇼핑몰코드를 스마트스토어2.0 으로 지정한 상태로 재확인 |
| 이카운트 측 **채널 개설 필요 여부** | `쇼핑몰추가요청` 버튼이 존재 | 버튼 클릭 시 요구사항 화면 확인 |
| OAPI **엔드포인트·인증 방식** | 매뉴얼은 외부 문서(`sboapica.ecount.com/.../OAPIManual`) | 매뉴얼 열람 또는 이카운트 기술지원 |
| **재고 정합성** 운영 방식 | 이카운트와 웹 재고의 마스터는 별개 | **김범신 대표 + 운영 책임자 결정 필요** |
| ERP → 웹 **배포 주체** | 이카운트 불가 → 카페24 API/네이버 API 중 선택 | 채널 전략 결정 후 진행 |
| Tri-B **추가구성상품** 취급 | 이카운트 수집 불가 | 웹 옵션으로 전개할지, ERP 는 기본 품목만 둘지 결정 |
