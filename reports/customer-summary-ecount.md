# 이카운트 ERP 연동 준비 — 고객용 작업 요약

**대상**: 김범신 대표 / CGI 이카운트 ERP 실계정
**조사 일자**: 2026-10-22 · **성격**: 실계정 화면 조사(읽기 전용). 운영 데이터 생성·수정·삭제 없음
**보안**: 계정번호·ID·암호·인증키 등 계정정보는 본 요약에 기재하지 않았습니다.

---

## 1. 무슨 일을 했나

CGI가 운영 중인 **이카운트 ERP 를 실제로 로그인해서 열어보고**, "공급처 상품을 이카운트에 넣고 네이버 스마트스토어와 연결하려면 뭐가 필요한가"를 **화면에서 직접 확인**했습니다. 문서나 요약본이 아니라 **실제 화면과 실제 엑셀 서식 파일**을 기준으로 했습니다.

확인한 항목: 품목 등록·조회·수정 / 품목 분류·품목코드 / 거래처 관리 / 재고 조회·입출고 / 주문·판매 관리 / 매출·매입 전표 / 엑셀 일괄 등록·다운로드 / API 및 쇼핑몰 연동 / **네이버 스마트스토어 연동 지원 여부**

---

## 2. 가장 중요한 결론 3가지

### ① 이카운트에는 "네이버 스마트스토어 주문 처리" 기능이 있습니다

쇼핑몰 관리 메뉴에 **34개 쇼핑몰**이 지원 목록으로 들어 있고, 그 안에 **스마트스토어2.0** 이 있습니다.
네이버 주문이 들어오면 → **신규 주문 수집, 주문 확인(수신/송신), 배송 처리, 취소, 반품, 교환**까지 이카운트 안에서 가능합니다. 즉 **주문 이후的业务 백오피스**는 이카운트로 충분합니다.

### ② 다만 "상품을 이카운트에서 네이버에 자동으로 올리는" 기능은 없습니다

같은 지원표에서 **'상품등록' 항목이 지원 불가(✕)** 로 나옵니다. 34개 쇼핑몰 **전부** 그렇습니다. 즉 이것은 네이버만 제한받는 게 아니라 이카운트 플랫폼 설계 자체입니다.

**→ 결론**: 이카운트의 역할을 **"주문·재고·회계 백오피스"** 로 확정하고, **상품 마스터를 웹(카페24/네이버)에 올리는 일은 별도 파이프라인**으로 분리하는 것이 맞습니다. 이카운트를 억지로 "스토어"로 쓰려는 설계는 피해야 합니다.

### ③ 삼아사운드·삼아스토어 상품을 이카운트에 넣는 일은 **추가 개발 없이 가능합니다**

이카운트에 이미 **엑셀 일괄 등록** 기능이 있고, 그 화면에서 **공식 서식 파일**(빈 양식)을 내려받을 수 있습니다. 그 양식의 헤더 주석까지 확인했는데, **어떤 칸에 무엇을 넣고 몇 자까지 되는지**가 전부 적혀 있습니다. (상세는 `reports/ecount-item-bulk-registration.md`)

**이 작업에서 새로 개발해야 할 것은 0건** 입니다. 양식 변환 스크립트만 있으면 됩니다.

## 3. 실제로 확인한 것 중 눈여겨볼 점

| 확인 내용 | 의미 |
|---|---|
| 이카운트 **품목에 '브랜드' 칸이 없습니다** | 브랜드·모델명·원산지 같은 값은 이카운트 기본칸이 아니라 **사용자 정의 추가칸**(문자형추가항목 5개 + 자유 입력칸 40개)에 넣어야 합니다. `문자형추가항목1`은 이미 "조달등록번호" 전용이라 브랜드/모델명용으로는 못 씁니다. |
| 웹 상품 **옵션(길이선택, 색상, 추가구성상품)** 구조와 이카운트 **규격** 구조가 다릅니다 | 웹 옵션을 그대로 이카운트 옵션으로 옮기는 것은 불가능합니다. 이카운트 쪽에는 **기본 변형 1개 = 1품목**으로 두고, 옵션 차이는 출고단가 10단(단가A~J) 또는 추가칸으로 관리해야 합니다. |
| 이카운트 **공급가는 웹에 없습니다** | 이카운트 안에서 유일하게 공급가가 기록되는 곳은 **매입/매출 전표의 '공급가액'** 칸입니다. 웹(삼아사운드·삼아스토어)에는 아예 공개되지 않습니다. 그래서 "공급가"는 이카운트 전표를 넣은 뒤에야 확정됩니다. |
| **쇼핑몰품목코드연결** 화면이 있음 | `쇼핑몰코드 / 품목코드 / 품목명 / 쇼핑몰품목key` 4칸 표입니다. **네이버 상품ID ↔ 이카운트 품목코드** 연결표이며, 이게 있어야 네이버 주문이 이카운트 주문서로 자동 낙하합니다. 엑셀 일괄 등록도 됩니다. |
| 현재 **쇼핑몰 채널이 1건도 등록되어 있지 않습니다** | 이카운트에 아직 스마트스토어(또는 카페24) 채널이 없습니다. 등록이 선행되어야 합니다. |
| **API 인증키가 아직 발급되지 않았습니다** | 이카운트 개방 API(OAPI) 키 발급 화면이 있으나 비어 있습니다. 키를 쓸 경우 **허용 IP 등록이 필수**이고, 만료 후 3개월이 지나면 키가 영구 삭제됩니다. |
| 전 화면에 **대용량 조회·엑셀 내보내기·오천건이상조회** 버튼 | 카탈로그 수천 건을 다룰 때 필요한 기능이 이미 다 있습니다. |

## 4. 앞으로 할 일을 권장 순서로

```
[1]  김범신 대표 확인 (아래 5.1의 결정 항목)
[2]  이카운트에 스마트스토어 채널 등록  (쇼핑몰관리 > 쇼핑몰등록)
[3]  API 인증키 발급 + 허용 IP 등록
[4]  삼아사운드·삼아스토어 상품 → 이카운트 품목 일괄 등록
       (웹자료올리기 17칸 1차 등록 → 브랜드/모델명 추가칸 2차 반영)
[5]  쇼핑몰품목코드연결 일괄 등록 (네이버 상품ID ↔ 이카운트 품목코드)
[6]  상품 마스터 배포는 별도 경로 (카페24 API 또는 네이버 오픈API)
[7]  검증: 네이버 주문 1건 → 이카운트 주문서 → 전표 → 재고 차감 → 취소 1건
```

## 5. 대표님께 확인 요청드릴 사항

### 5.1 지금 결정이 필요한 것

| # | 결정 항목 | 선택지 |
|---|---|---|
| 1 | **이카운트의 역할 범위** | (A) 주문·재고·회계 백오피스로만 사용 / (B) 웹까지 이카운트가 관리 |
| 2 | **상품 마스터 배포 주체** | (A) 카페24 API(삼아스토어 경유) / (B) 네이버 오픈API 직접 / (C) 사람이 수동 등록 |
| 3 | **ERP 재고 ↔ 웹 재고 정합성 책임** | 웹 재고를 ERP 로 pull 하는지, ERP 재고를 웹으로 push 하는지, 사람이 맞추는지 |
| 4 | **공급가 소스** | 이카운트 전표가 유일 소스인지, 별도 계약 단가표가 있는지 |
| 5 | **Tri-A(삼아사운드) 재고 취급** | Tri-A 는 웹에서 재고 미관리가 확인됐습니다. 이카운트에서도 **재고 미관리(수량관리 제외)** 로 둘지 |

### 5.2 추후 정보가 필요한 것

- 이카운트에서 **빅데이터/데이터내보내기** 화면 구조가 이번 조사에서 확인되지 않았습니다(프로그램만 확인). 대량 정산 데이터가 필요하면 한 번 더 봐야 합니다.
- 이카운트 **WMS(창고관리)** 화면도 이번에는 렌더가 안 확인됐습니다.
- 스마트스토어2.0 채널을 선택했을 때만 나타나는 전용 인증칸(네이버 OAuth 등)은 신규 화면에서 채널을 고른 상태로 다시 확인해야 확정됩니다.
- **웹 옵션(추가구성상품)을 이카운트에서 다룰지에 대한 정책**이 필요합니다. 이카운트는 이 개념을 지원하지 않습니다.

## 7. 이 조사를 하지 않은 것 (정확히 밝힘)

- 실제 품목·거래처·주문·재고 **데이터는 한 건도 가져오지 않았고**, 저장소에도 옮기지 않았습니다.
- **계정정보(회사번호·ID·암호·인증키)** 는 이 문서와 저장소 어디에도 없습니다.
- **새 품목/거래처/전표를 실제로 만들지 않았습니다.** 화면을 보고, 빈 서식 파일만 내려받았습니다.
- 실제 일괄 등록 실행은 하지 않았습니다. 승인 후 **5~20건 샘플 선등록 → 확인 → 전량** 순으로 진행하는 것을 권합니다.
