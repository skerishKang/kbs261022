# 상품 일괄 등록 방법 (이카운트 ERP)

> 본 문서는 실계정 화면에서 **확인·다운로드한 템플릿**을 기준으로 작성했다.
> 계정정보·실데이터는 포함하지 않는다. 실제 일괄 등록 **실행**은 본 단계에서 수행하지 않았다(운영 데이터 생성 금지).

---

## 1. 두 가지 일괄 등록 방식

`Self-Customizing > 다운로드 > 엑셀자료올리기기능` (`E000129`) 화면이 두 방식을 공식 안내한다.

| | 엑셀자료올리기 | **웹자료올리기 (권장)** |
|---|---|---|
| 요건 | Excel 2007 이상(오피스 365 제외) + PC 설치 프로그램 | **모든 엑셀 버전** |
| 전송 방식 | 엑셀 안에서 직접 전송 | 메뉴에서 파일 업로드 |
| 절차 | 설치 후 엑셀 내 사용 | `웹자료올리기` → `엑셀서식내려받기` → 기입 → `자료올리기` |
| 장점 | 대용량 반복 전송 | **설치 불필요, 서식 공식 제공, 자동화(Playwright) 용이** |

> **결론: 웹자료올리기를 표준 경로로 채택한다.** 브라우저 자동화와 조합하기 쉽고, 어제랑 다른 사람이 재현해도 설치 절차가 없다.

---

## 2. 표준 절차 (품목 기준, 5단계)

```
STEP 1  준비      삼아사운드/삼아스토어 공개 수집 결과 → 상품 마스터 CSV
                  (이 저장소 모델 B 산출 스키마: 40컬럼)

STEP 2  코드 설계  ERP 품목코드(prod_cd) 채번 규칙 확정
                  확정: SS-<통합키 seq> (삼아사운드) / SM-<통합키 seq> (삼아뮤직)
                  카페24 product_code 는 4,234건 중 856건이 중복 → 키로 사용 불가

STEP 3  변환      상품 마스터 → 이카운트 템플릿 17컬럼 매핑
                  + 확장필드(브랜드/모델명) 반영

STEP 4  검증      5~20건 선등록(샘플) → 등록 결과 '결과' 컬럼 확인
                  → 오류 유형별 템플릿 보정 → 전량 등록

STEP 5  확인      품목등록 리스트에서 조회(품목코드/품목명/규격/그룹/사용구분)
                  + Excel 버튼으로 결과 대조 추출
```

## 3. STEP 3 상세 — 마스터 → 템플릿 변환표

템플릿: `품목등록 > 웹자료올리기 > 엑셀서식내려받기` → `Template.xlsx` (시트 `품목등록`)

| 템플릿 열 | 컬럼명 | 마스터 출처 | 변환 규칙 | 필수 |
|---|---|---|---|---|
| A | 품목코드 | `product_code` | **사용하지 않음**(중복). `SS-{seq}`(삼아사운드) / `SM-{seq}`(삼아뮤직) 생성. 20자 이내·중복 0 검증 | Y(생성) |
| B | 품목명 | `product_name` | 공백/기호 정규화(줄바꿈 제거). 최대 100자 | Y |
| C | 바코드 | `source_item_code` | 카페24 `item_code`(예: P0000DQK000A) 가 **전체에서 유일한 경우에만** 기입. 중복 코드는 공란 | - |
| D | 규격구분 | (신규 컬럼) | Tri-B 는 `1`(규격명). Tri-A 도 값이 있으면 `1` | - |
| E | 규격 | `model` | Tri-B `model` 값. Tri-A 는 `model` 미확정이면 **빈 값**(추정 금지) | - |
| F | 단위 | (신규 컬럼) | 기본 `EA`(개). 규격이 1m/3m 이어도 `EA` | - |
| G | 품목구분 | (신규 컬럼) | `3`(상품) 고정 — CGI 는 판매용 상품이므로 | - |
| H | 세트여부 | (신규 컬럼) | `0`(세트아님) 고정 | - |
| I | 재고수량관리 | (신규 컬럼) | Tri-B `1`(수량관리대상, 2,294건) / **Tri-A `0`(수량관리제외, 2,281건)** | - |
| J | 입고단가 | (신규 컬럼) | **공란 유지.** 웹에 공급가 없음. ERP 전표에서 확정 | - |
| K | 입고단가 VAT포함여부 | (신규 컬럼) | `0`(포함안함) | - |
| L | 출고단가 | `published_price` | Tri-B 는 `published_price`(2,117건). **Tri-A·미공개 2,458건은 공란** | - |
| M | 출고단가 VAT포함여부 | (신규 컬럼) | `1`(포함) | - |
| N | 부가세율(매출) | (신규 컬럼) | `10` | - |
| O | 부가세율(매입) | (신규 컬럼) | `10` | - |
| P | 검색창내용 | `summary` | `브랜드 모델명 품목명` 순으로 조립, 100자 초과 시 절단 | - |
| Q | 품목공유여부 | (신규 컬럼) | `0`(공유안함) | - |
| (결과) | 결과 | — | 시스템 출력 | - |

> **헤더 문구 주의**: K열 헤더는 `입고단가 VAT포함여부` 처럼 **공백이 포함**된다. 임의로 붙여 쓰면 업로드가 거부될 수 있으므로 다운로드한 서식을 그대로 쓴다.

**공란 유지 규칙 (추정 금지)**: `published_price` 가 없는 Tri-A 상품의 L열, `dealer_price` 는 J열에 **전혀 매핑하지 않는다.** 숫자를 채우면 "공급가 공개" 라는 잘못된 사실이 ERP 안에 생긴다.

### 3.1 확장 필드(브랜드/모델명) 반영 — 2단 전략

17컬럼 기본 템플릿에는 브랜드·모델명 칸이 없다. 두 가지 경로가 있다.

| 경로 | 절차 | 장단점 |
|---|---|---|
| **A. 2차 변경(권장)** | 1차: 17컬럼으로 전량 등록 → 2차: `웹자료올리기 > 변경하기` 탭에서 `변경항목선택`으로 `cont2`(브랜드)·`cont3`(모델명) 선택 → 동일 `prod_cd` 로 변경 업로드 | 템플릿 변경 불필요. 등록/변경 책임 분리 |
| B. 1차부터 확장 | `항목추가` 로 `cont2`~`cont6`, `ADD_TXT_01~10` 등을 추가한 개인 템플릿을 만들어 1차 등록부터 반영 | 1회성이지만 **개인 서식 관리 부담** |

> **권장 = 경로 A.** 기본 템플릿(공식)이 바뀌어도 영향받지 않고, 감사 추적이 쉽다.

### 3.2 `cont2`~`cont6` 배정 규칙 (확정 제안)

| 필드 | 배정 | 비고 |
|---|---|---|
| `cont1` | **조달등록번호** (전용) | **브랜드/모델에 사용 불가** |
| `cont2` | **브랜드** | 원문 표기 정규화본 |
| `cont3` | **모델명** | Tri-B `model` 값, Tri-A 는 규칙 추출값(미확정 시 공란) |
| `cont4` | **제조사** | Tri-A `manufacturer` = 제조사, Tri-B 는 공란 |
| `cont5` | **원산지** | `country_of_origin` |
| `cont6` | **공급사/계열** | Tri-A / Tri-B 구분, 근거 페이지 |
| `no_user1`~`no_user10` | 수치 속성 | 패키지 수량, 무게, 케이스 당 수량 등 |
| `ADD_TXT_01~10` | 자유 기술 | 색상, 재고표시명, 검색 태그, 옵션 요약 등 |
| `ADD_LTXT_01~10` | 장문 | 상세 규격, 주의사항 |
| `ADD_NUM_01~10` | 수치 | 옵션 추가금액 등 |
| `ADD_DATE_01~10` | 일자 | 출시일, 단종 예정일 등 |

## 4. 거래처 일괄 등록 (필요 시)

`거래처등록 > 웹자료올리기` 템플릿: `No. · 거래처코드 · 상호(이름) · 대표자명 · 업태 · 종목 · 전화 · Fax · Email · 검색창내용 · 주소1 우편번호 · 주소1 · 결과`

- **거래처코드** = 사업자번호(또는 신규 채번) 를 쓰면 추적성이 좋아진다.
- 공급처(삼아사운드/삼아스토어), 네이버 스마트스토어 판매자 계정, 물류/대행사는 모두 **거래처로 등록**되어야 전표·여신·단가 관리가 된다.
- 웹자료올리기로 생성된 거래처는 **여신/단가** 탭에서 직접 입력해야 한다(공급가는 여기서만 확정된다).

## 5. 쇼핑몰 품목코드 연결 (연동의 다리)

`쇼핑몰관리 > 쇼핑몰품목코드연결 > 웹자료올리기` 템플릿:

```
No. · 쇼핑몰코드 · 품목코드 · 품목명 · 쇼핑몰품목key · 결과
```

| 컬럼 | 채우는 값 | 비고 |
|---|---|---|
| 쇼핑몰코드 | `쇼핑몰관리 > 쇼핑몰등록` 에 등록한 스마트스토어2.0 의 `OPENMARKET_CD` | **먼저 쇼핑몰을 등록해야 한다** |
| 품목코드 | ERP `prod_cd` | 1:1 |
| 품목명 | ERP `prod_des` | 대조용 |
| 쇼핑몰품목key | **네이버 스마트스토어 상품ID** 또는 **카페24 `product_no`** | 웹 → ERP 역방향 키 |

> 이 표가 **웹 주문이 이카운트 주문서로 자동 낙하되기 위한 전제 조건**이다. 이 매핑이 없으면 전표 자동생성(`ERP전표생성(출고)`)이 성립하지 않는다.

## 6. 창고별 안전재고 일괄 등록

`품목등록 > 웹자료올리기 > 창고별안전재고올리기` 탭 템플릿:

```
No. · 품목코드 · 창고코드 · 안전재고수량 · 결과
```

- 창고코드는 `창고등록`(E040102) 의 `창고코드` 와 동일해야 한다.
- **안전재고수량은 실재고가 아니다.** 재고현황(E040701) 의 `balQty` 와 다른 값이므로 혼동 금지.

## 7. 오류 대응(실제 오류 메시지는 미확인 — 신규 건)

`자료올리기` 후 팝업의 `결과` 컬럼에 건별 사유가 출력된다. 아래는 **오류가 났을 때의 확인 순서**이며, 실제 오류 코드 사전은 아직 없다.

| 증상 | 확인할 것 |
|---|---|
| 품목코드 중복 | `품목등록` 리스트에서 동일 `prod_cd` 존재 여부(변경 업로드가 아니라 신규 업로드했을 때) |
| 규격그룹 코드 오류 | `규격구분` 이 `2`/`4` 인데 `규격` 에 그룹 **코드**가 아니라 이름을 넣은 경우 |
| 품목구분 오류 | `품목구분` 값이 `0`~`4`,`7` 외의 값 |
| 수량관리 기본값 | `재고수량관리` 공란 → 기본양식 기본값 적용됨(주의) |
| 금액 자릿수 | 정수 12자 / 소수 6자 초과 |
| 세트여부 불가 | `품목구분` 이 상품(3)/제품(1) 이 아닌데 `세트여부` 를 넣음 |

## 8. 실행 시 주의사항(실계정 실측 기반)

1. **`오천건이상조회`**: 대량 등록 후 대조 시 사용. 목록은 기본 1페이지 20~26행.
2. **`사용중단포함` / `사용안함`**: 사용중단 품목은 기본 조회에서 빠진다. 대조 시 반드시 포함.
3. **동시 작업 금지**: 같은 메뉴를 다른 사람이 편집 중이면 `web 자료올리기` 전표가 꼬인다. 사전에 담당자 확인.
4. **등록 직후에는 재고/단가가 초기값(0/기본값)이다.** 웹 데이터로 채우려면 `변경하기` 탭 2차 업로드가 필요하다.
5. **이 단계에서 실제 일괄 등록은 수행하지 않았다(2026-10-23 실계정 재확인).** 승인 후 샘플 5~20건 선등록 → 검증 → 전량 순으로 진행할 것.
6. **기존 ERP 964건과 코드가 겹치지 않는다.** 기존 품목은 `000001`·`A...` 계열이고 신규는 `SS-`/`SM-` 이므로 코드 충돌은 없지만, 동일 상품이 두 코드로 공존할 수 있다. 등록 전에 이름/모델 대조 결과(일치 25쌍·후보 62쌍)를 참고해 중복 등록 여부를 담당자가 판단해야 한다.
