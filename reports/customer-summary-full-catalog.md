## 1. 무슨 일을 했나

"상품 39건 샘플로 그만두지 말고, **지금 확인되는 상품 전부를** 상세까지 확보해 검증했다."

| | 결과 |
|---|---|
| 수집 대상 | Tri-A 2,281건 + Tri-B 2,294건 = **4,575건 전량** |
| 수집 실패 | **0건** |
| 브라우저 실화면 교차검증 | 48건(층화추출) **100% 일치** |
| 검증 중 발견해 고친 실제 오류 | **2건**(아래 3장) |
| Excel DB | 7개 시트 · 4,575행 (로컬 보존) |
| HTML 쇼핑몰 | 기존 코드 그대로 **4,575건 연결 가능** (개발 불필요) |

기존에 만들어둔 수집 도구를 **그대로 재사용**했고, 새로 만든 것은 "전량을 돌리는 오케스트레이터 + 검증기 + 엑셀 빌더"뿐이다.

## 3. 검증에서 실제로 잡아 고친 오류 2건

브라우저로 실제 화면을 열어 대조한 덕에 드러난 **진짜 데이터 오류**입니다. 둘 다 고쳤습니다.

| 오류 | 무슨 일이었나 | 고친 뒤 |
|---|---|---|
| **상품 이미지에 엉뚱한 그림이 섞여 있었음** | 삼아스토어 상품 하나에 상품 이미지 4장이 아니라 **12개**가 들어 있었습니다. 사이트 배너·편집기 이미지·외부 CDN 그림까지 "상품 이미지"로 기록된 상태 | 삼아스토어 358번 상품 → **4장**으로 정정 |
| **대표 이미지(큰 그림)가 통째로 빠져 있었음** | 삼아사운드 776번 상품의 큰 대표 이미지가 수집되지 않고 작은 것만 남아 있었습니다(원본 코드의 공백 처리 오류) | **큰 것+작은 것 2장**으로 정정 |

→ 이 오류는 **기존 수집 도구의 문제**라, 해당 PR 담당자에게 수정 요청으로 남겼고 이 브랜치에서는 **원본을 건드리지 않고** 수집 단계에서 바로잡았습니다.

## 4. "상품이 약 20,000개"라는 말씀에 대해

**확인되지 않았습니다(UNVERIFIED).** 확인 가능한 수량만 정리합니다.

| 측정값 | 개수 | 비고 |
|---|---:|---|
| **지금 공개 진열된 상품 합계** | **4,575** | 이번에 전량 실측 |
| 삼아스토어 **숨김 포함 스토어 내부 전체** | 3,694 | 검색 API 실측 |
| ├ 그중 **목록에 안 나오고 숨겨진 것** | 1,400 | 그중 **326건은 "진열돼 있지만 미판매"** → 판매중지·품절 후보 |
| 옵션 SKU(item_code) 기준 | 3,401 | |
| **이카운트 ERP 품목 마스터** | **964** | 실계정 화면 실측(38페이지) |
| 이카운트 ERP 거래처 | 1,505 | 실계정 화면 실측(58페이지) |

**어떤 조합으로도 20,000 에 도달하지 않습니다.** 20,000 은 아래 중 하나일 가능성이 있지만 **근거가 없어 단정하지 않습니다.**

1. **집계 기준이 달랐을 가능성** — 상품 ID / 옵션 SKU / 규격 묶음 중 다른 기준
2. **삼아사운드·삼아스토어 외에 세 번째 공급처가 있을 가능성** — 현재는 확인된 공급처가 2곳뿐
3. **다른 시점·다른 채널 기준** — 대표님 진술 시점의 규모

> **확인되지 않은 상품을 만들어 20,000 을 맞추지 않았습니다.** 4,575건(공개 진열) + 숨김 1,400건(판매중지 포함)을 분리해 확보했습니다.

**대표님께 여쭙고 싶은 것**

1. 20,000 은 **상품 ID 기준**인가요, **옵션 SKU 기준**인가요, **규격 묶음 기준**인가요?
2. **삼아사운드·삼아스토어 외에 세 번째 공급처**가 있나요?
3. 20,000 을 산출한 **시점·근거 자료**를 알려주시면 대조해 보겠습니다.

## 5. 이제 가능한 것

### 5.1 HTML 쇼핑몰에 전체 상품 표시 (개발 불필요)

기존에 만들어둔 빌더에 **전체 마스터 파일을 그대로 넣으면** 39건 → **4,575건**으로 확장됩니다. `site/` 코드는 건드리지 않았습니다(다른 작업과 충돌 방지).

```
python tools/build_catalog_data.py --master-csv <전체마스터.csv> --categories <카테고리.csv>
```

### 5.2 Excel DB (7개 시트)

`통합상품` · `공급처원본` · `브랜드·카테고리` · `카테고리목록` · `중복후보` · `누락·검증현황` · `향후네이버·이카운트`

Excel 과 HTML 이 **같은 원본 파일에서** 나오므로 **표시되는 상품 수와 식별자가 자동으로 일치**합니다.

### 5.3 이카운트 연계 준비

| 이카운트 칸 | 채울 값 | 상태 |
|---|---|---|
| 품목코드 | 카페24 상품코드(P+7자리) | 4,575건 준비 |
| 브랜드(문자형추가항목2) | 공급처 브랜드 | 4,575건 준비 |
| 모델명(문자형추가항목3) | 모델명 | Tri-B 1,740건 준비 / Tri-A 는 **상품명에서 추출 필요** |
| 규격(SIZE_DES) | 모델명 fallback | 준비 |
| 출고단가(out_price) | 공개 판매가 | **Tri-B 2,120건만** (Tri-A 는 공개 판매가 없음) |
| 입고단가(in_price) | 공급가 | **확인 필요 — 공개 없음** |

> 이카운트 채널(스마트스토어2.0)은 아직 등록되지 않았고, 이카운트는 **상품 등록 기능을 제공하지 않습니다.** 주문 처리는 이카운트로 충분하되 **상품 마스터 배포는 별도 경로**가 필요합니다(PR #21 분석 참조).

## 6. 하지 않은 것 (정확히 밝힘)

- **계정정보**(회사번호·ID·암호·인증키)를 이 저장소에 기록하지 않았습니다.
- **공급가·실재고·CGI 판매가·취급 승인 여부**를 지어내지 않았습니다(전부 NULL).
- **운영 데이터를 만들지 않았습니다.** 조회와 빈 서식 파일 다운로드만 했습니다.
- **대용량 원본(마스터 CSV 11.7MB / XLSX 2.5MB)을 공개 저장소에 올리지 않았습니다.** 로컬에 보관했고 GitHub 에는 재현 코드·통계·검증 결과만 올렸습니다.
- **HTML 사이트 파일(`site/`)과 다른 에이전트의 수집기·스키마를 수정하지 않았습니다.**
- **삼아스토어 숨김 상품 1,400건**은 상세 페이지를 수집하지 않았습니다(공개 진열 대상 아님). 목록 정보만 확보했습니다.
- **실일괄 등록(ERP 쓰기)은 하지 않았습니다.**
