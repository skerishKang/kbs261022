# AI 투찰가 분석 엔진 설계 (bid/ANALYSIS_DESIGN.md)

상세 화면의 "AI 투찰가 분석" 카드는 회원 전용(흐림+🔒)이며, 엔진은 데이터가 확보되는 이후 단계에
활성화한다. 계산기 화면은 만들지 않는다. 데이터가 없는 시점에 값을 그려 넣지 않는다 — 회원 전용
항목의 화면 예시 수치는 레이아웃 규격 확인용이고, 실제 서비스에서는 아래 입력 데이터로만 계산한다.

## 1. 입력 데이터

1. **기초금액·낙찰하한율** — 나라장터 공고 상세(회원 전용 수집 항목). 낙찰하한율은 공고문·적격심사
   세부기준의 값이 최종이며, 기준표는 §3의 확인값을 참조용으로만 쓴다.
2. **개찰 결과 사정률 분포** — 오픈데이터 "조달청 나라장터 낙찰정보서비스"(§4)로 발주기관·물품분류별
   사정률 히스토리를 수집한다. 사정률 원본 데이터는 현재 수집본에 없다.
3. **참가업체 수** — 개찰 결과의 투찰(참가) 업체 수.

## 2. 산출 정의

1. **낙찰하한가** = 기초금액 × 낙찰하한율(공고 값 우선, 없으면 같은 발주기관·물품분류 최근 하한율
   중앙값 — 이때 표본 수를 함께 표기)
2. **사정률 분포** = 같은 발주기관 × 같은 물품분류(부족하면 상위 공종으로 확장) 개찰 결과의 사정률
   히스토그램. 구간 5~10개, 최근 2년. 표본 수를 그래프와 함께 표기한다.
3. **추천 투찰 구간** = 사정률 분포의 중위권(25~75백분위)에 대응하는 투찰가 구간. 낙찰 가능성은
   분포 백분위로 환산해 표기하되 확정적 표현("반드시", "100%")은 쓰지 않는다.
4. **예상 경쟁 수** = 해당 발주기관 최근 개찰의 참가업체 수 중앙값(±분산).

## 4. 데이터 수집 — 조달청 나라장터 낙찰정보서비스 (오픈데이터)

- 카탈로그: https://www.data.go.kr/data/15129397/openapi.do (확인된 endPoint:
  `https://apis.data.go.kr/1230000/as/ScsbidInfoService`, 제공: 조달청 조달데이터관리팀)
- 상세 기능(카탈로그 한국어 명칭, 23개): 낙찰된 목록 현황 물품/공사/용역/외자조회, 개찰결과 물품/공사/
  용역/외자 목록 조회, 예비가격상세 목록 조회, 개찰완료·유찰·재입찰 목록 조회 등
- 수집 대상: **개찰결과 목록**(낙찰업체·낙찰금액), **낙찰된 목록**(사정률·투찰률), 참가(투찰) 업체 수,
  기초금액 공개 값 — 표본·기간은 §2와 같다.
- REST operation(3차 확인): 낙찰된 목록 `getScsbidListSttus{Thng,Cnstwk,Servc,Frgcpt}`, 개찰결과
  `getOpengResultListInfo{Thng,Cnstwk,Servc,Frgcpt}`, 예비가격 상세 `getOpengResultListInfo{...}PreparPcDetail`.
  기초금액은 입찰공고정보서비스의 `getBidPblancListInfo{Thng,Cnstwk,Servc}BsisAmount`로 받는다.
  응답 필드명은 `RESULT_FIELD_CANDIDATES` 후보로 받고 키 발급 후 실응답으로 확정한다.
- 저장 형식: `bid/assets/data/result-data.js`(`window.CGI_RESULT_DATA`) — results.html과
  분석 카드가 읽는다. 필드: `no`·`ord`·`base_amount`(기초금액)·`success_rate`(사정률)·
  `low_rate`(낙찰하한율)·`bid_amount`(낙찰금액)·`bidder_count`(참가 수)·`winner`(낙찰업체).
  파일이 없으면 두 화면은 "개찰 후 반영"을 유지한다(지어내지 않음).

## 5. 사정율 통계 — 8차 파이프라인 (rate_stats.py)

상세 화면의 "사정율 통계" 섹션은 8차에서 파이프라인만 먼저 구축했다. 실데이터가 모이기 전에는
**숫자를 하나도 표시하지 않는다**(빈 상태 문구만).

### 계산식
- **사정률(%) = 예정가격 ÷ 기초금액 × 100** (소수 4자리에서 반올림해 계산, 화면은 2자리)
- **편차(%) = 사정률 − 100**
- **히스토그램** = 0.1%p 구간별 건수. 구간은 `[k×0.1, (k+1)×0.1)` — 99.95는 99.9 구간,
  100.05는 100.0 구간이다(내림 배치). 빈 구간은 내보내지 않는다.

### 표본 묶음 우선순위(n ≥ 30)
1. 같은 발주기관
2. 같은 분류(물품/공사/용역) + 같은 금액대(추정가격: 5천만 미만 / 5천~1억 / 1억~10억 / 10억 이상 — 목록 필터와 같은 구간)
3. 같은 분류 전체

처음 n≥30을 충족한 묶음을 쓰고 **어떤 묶음을 썼는지 결과에 기록**한다(화면 "사용한 묶음").
어느 묶음도 n<30이면 "표본 부족" — 통계 숫자를 만들지 않는다. 표본 기준은 §5의 원칙(근거 표기)에 따라
코드 상수 `MIN_SAMPLE=30`으로 고정돼 있다.

### 산출물
- `tools/procurement/rate_stats.py` — 계산 전담(순수 함수, 단위테스트 대상)
- `build_bid_data.py`가 개찰결과 예비가격상세 수집분(`reports/data/procurement/openg_result_price.json`,
  수집기 `--opening-price` 산출)과 bid 목록을 조인해 `bid/assets/data/rate-stats.js`
  (`window.CGI_RATE_STATS`)을 생성한다. 실데이터가 없으면 `{collected:false, bundles:{}}` 빈 구조만.
- `validate_bid_data.py`가 rate-stats 스키마를 검증한다: collected:false면 숫자 필드가 있으면 안 되고,
  collected:true면 모든 묶음이 n≥30·평균 범위·히스토그램 합계=n을 만족해야 한다.

### 미검증 항목(키 발급 후 확정)
- operation: `getOpengResultListInfo{Thng,Cnstwk,Servc,Frgcpt}PreparPcDetail` — 공공데이터포털
  15129397(낙찰정보서비스) 오퍼레이션 목록 확인분. **실호출 전**이라 코드에 `★미검증(키 발급 후 확정)` 표시.
- 응답 필드 후보: `PREPAID_FIELD_CANDIDATES`(기초금액·예정가격·복수예비가격 여부·추첨 여부·개찰일).
  실응답 키로 확정할 때까지 후보 나열로 받는다.
- fixtures의 `sample_openg_result_prepar_pc_detail_thng.json`은 문서 예시 양식을 본뜬 **테스트 전용 견본**이며
  bid-data·rate-stats 산출물에 절대 섞이지 않는다(빌드가 fixtures 폴더를 읽지 않는다 — 테스트로 고정).

## 6. 제약

- 표본이 기준(n≥30, §5 묶음 규칙)에 못 미치면 구간 대신 "표본 부족"을 표기한다(지어내지 않음).
- 엔진은 Worker(회원 인증 뒤)에서만 계산하고, 원시 히스토리를 화면에 노출하지 않는다.
- 분석 근거(표본 수·기간·출처)를 화면에 함께 표기한다. 위조·과장 금지.

## 7. 단계

① 화면 골격(4차 — 흐림+🔒) → ② 개인화·CGI 품목 탭(7차) → ③ **사정율 통계 파이프라인 사전 구축(8차 —
계산 모듈·산출물 스키마·빈 상태 화면)** → ④ 예비가격상세 실수집(키 발급 후, ★미검증 해소) →
⑤ 사정율 통계 공개 + 추천 구간(§2)·엔진(회원 전용).
