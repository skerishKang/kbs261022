# bid/ — CGI 입찰정보 (kbs261022 이슈 #188 1단계 UI)

나라장터 입찰공고를 검색·분류해 보여 주는 정적 화면 5종. 이 브랜치(feat/bid-ui-261105)에는
**화면만** 포함된다 — 서버·D1·결제·회원가입 로직 없음. 데이터는 저장소의 공개 수집 결과를
변환해 정적 JS로 넣는다.

## AI 투찰가 분석 엔진 설계

**[bid/ANALYSIS_DESIGN.md](ANALYSIS_DESIGN.md)** 로 옮겼다 — 입력 데이터·산출 정의·낙찰하한율 기준표
(확인된 값과 출처 URL)·낙찰정보 API 수집 형식·제약·단계는 그 문서에서 관리한다.

## 데이터

- `bid/assets/data/bid-data.js` — `tools/procurement/build_bid_data.py`가 생성(3차에 저장소로 반입, CI가 `--check`로 재현성 확인).
  장기(상시) 접수 공고는 `lt: true`로 표시해 D-day 대신 "상시 접수"로 보여 준다. 마감일이 원본에 없는 공고는 개찰일시로 상태를 정한다.
  변경·재공고는 목록의 마감·개찰 날짜를 우선한다(상세 보강은 원 공고 차수를 읽어 날짜가 낡을 수 있음).
  원본: `data/procurement/g2b_real_bids.json`(384건) + `reports/data/procurement/g2b_detail_enrichment.json`
  (상세 보강: 추정가격·예산·계약방법·개찰일시). 취소공고 18건 제외 → 366건, 추정가격 314건.
- `snapshot: 2026-10-23` — 수집일. 화면의 "오늘 마감", D-day, 진행/개찰 완료 상태는 **실제 오늘
  (한국 시간)** 기준으로 계산하고, snapshot은 수집일 표기와 시범 데이터 판정에만 쓴다(11차).
  수집일이 오늘보다 2일 이상 전이면 모든 화면 상단에 "시범 데이터 — … 수집분입니다" 띠를 두고,
  메인의 오늘 마감·마감 임박 표와 숫자를 숨기며 목록 기본 정렬을 공고일 최신순으로 바꾼다.
  수집일이 오늘·어제면 원래 화면(마감 임박·오늘 마감)이 그대로 나온다.
- 기초금액·낙찰하한율·적격심사 세부기준은 수집 데이터에 없는 값으로, 회원 전용 화면 표시에만 사용한다.

### 분류(2차 개정)

- 업무구분 우선순위: **나라장터 원본 업무구분 필드**(task_div/bsnsDivNm 등 — 현재 수집본에는 미포함,
  코드 준비 완료) → **물품분류번호(items[].class_no) 존재 시 구매**(125건) → **키워드 추정**(241건).
- 키워드 추정은 `유지보수`를 공사 '보수'와 분리(용역 기본, `단가공사` 등 공사 명시 시 공사),
  `대행`·`사업자 선정`을 용역에 추가. 전체 분포: 구매 148 · 공사 66 · 용역 152.
- 표본 30건(366건 중 12번째마다) 검증: 제목·품명 기준 수동 판정 대비 **30/30(100%)**.
  원본 필드가 부재하므로 기준은 수동 판정이며, 수집기에 업무구분 캡처가 추가되면 자동 대체된다.

### 수집기(2차 시도, 2026-11-05)

- 기존 Playwright 수집기(`g2b_notice_collector.js`) 라이브 재실행은 나라장터 접근 차단으로 실패 —
  `BBID0001.do` 직접 접근이 "시스템 접근 안내(올바르지 않은 URL 접근)"로 막히고(헤드리스·헤디드·
  실사용 브라우저 공통), 메인 메뉴는 WebSquare JS 네비라 폼 제출 없이 목록 도달 불가.
  상세 엔드포인트 HTTP 재현도 500. → 기존 데이터 유지, 기준일 2026-10-23.
- **오픈데이터 수집기 신설: `tools/procurement/g2b_openapi_collector.py`** —
  공공데이터포털 "조달청_나라장터 입찰공고정보서비스"(BidPublicInfoService04).
  - 키는 환경변수 `G2B_OPENAPI_KEY`로만 받고, 코드·로그·커밋에 값을 남기지 않는다.
    키가 없으면 안내 출력 후 종료(0) — 기존 bid-data.js 는 유지.
  - `--dry-run`은 실제 전송 없이 요청 URL을 키 마스크로 미리보기한다.
  - 물품·공사·용역·외자 operation별 목록 수집(`...Thng/Cnstwk/Servc/Frgcpt`, 공고일 기준 `--days` N일을 `--chunk-days` 구간으로 나눠 구간당 100건×최대 10페이지),
  - `--enrich`: 기초금액(`...BsisAmount`)·참가가능지역(`...PrtcptPsblRgn`) 보강,
    `--write-bid-data`로 bid/assets/data/bid-data.js 재생성(기준일 = 수집일).
  - 업무구분은 응답 `bizDivNm`(원본)을 분류에 우선 사용(물품/외자/기타→구매 표기).
  - 3차 정정: 공사는 `Cnstwk`(이전 `Constr`는 없는 이름), 서비스 경로는 `ad/BidPublicInfoService`(env `G2B_OPENAPI_BASE`로 변경 가능).
    응답 필드명은 키 발급 후 실응답으로 확정하고 `tools/procurement/fixtures/openapi_bid_list_sample.json`을 실응답으로 바꾼다.

## 구조·디자인 규약

- 저장소 루트의 `site/`(쇼핑몰)·`website/`(홈페이지)와 같은 폴더-단위 구성을 따른다.
  브랜드 토큰은 `site/assets/css/cgi-catalog.css`와 동일(공식 그린 `#07913A`·Pretendard·라운드 8px)하며,
  이번 화면은 자체 `bid/assets/css/bid.css`로 토큰을 복제해 다크 모드 토큰을 추가했다.
- 폰트: Pretendard 변수(dynamic subset) CDN 1줄 + 기존 폰트 스택 폴백.
- 숫자(금액·일시·D-day·공고번호)는 `tabular-nums`. 다크 모드는 시스템 설정 기본 + 헤더 버튼 수동 전환.
- 잠금 항목은 로그인 벽이 아니라 **값 흐림 + 🔒 + "회원 전용" 칩**으로 경계를 보여 준다.
- 메인 히어로는 2단 그리드(≥1100px): 좌측 검색·현황 숫자 카드·분류 바로가기, 우측 "마감 임박 TOP 5"
  사이드 패널. 1100px 미만에서는 사이드 패널이 아래로 내려온다.
- 분류 카드는 이름·건수를 세로 스택으로 고정해 어색한 줄바꿈이 없고, 390px에서도 3열 균등 소형 카드
  (혼자 남는 카드 배치 없음). 900px 미만에서 헤더 검색창은 아이콘 버튼으로 접히고, 누르면 전체 폭
  검색창이 열린다. 같은 폭에서 필터는 하단 시트로 연다.
- 지역은 원본 지역제한(region_names/region_text) → 기관명·공고명 키워드 추정 순으로 판별하고,
  판별되지 않으면 "지역 미지정" 문구 대신 **칸 자체를 숨긴다**(카드 메타·상세 표 모두).
- `../site/terms.html`, `../site/privacy.html`, `../website/index.html` 상대 링크는
  배포 루트에 `site/`·`website/`·`bid/`가 같은 오리진에 나란히 있을 때(배치 A) 동작한다.

## 배포 (CTO 확인용)

- Pages 프로젝트는 수동 업로드 방식(문서: `docs/CGI_DEPLOYMENT.md`, PR #175 메모).
  이 폴더는 세 번째 Pages 프로젝트(예: `cgibid`)로 올리거나, 기존 배포 루트에 `bid/` 폴더를 함께 넣어
  올리면 된다. 머지와 배포는 별개이므로 미리보기는 `wrangler pages deploy bid --project-name <신규>`
  로 확인하는 것을 권장한다. 이 브랜치에서 배포·푸시는 수행하지 않았다.
- 다음 단계(2차): 수집 파이프라인(Worker cron + D1), 회원 세션(기존 cgi-quote-api 패턴),
  AI 도우미·사정율 분석·투찰가 계산기.
